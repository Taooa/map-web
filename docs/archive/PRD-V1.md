# Spatial Data Toolkit V2 产品需求文档

> 文档状态：Draft  
> 产品版本：V2 产品重构（首个交付范围按本文 V1/MVP 定义）  
> 更新日期：2026-07-28

## 0. 文档说明

### 0.1 背景

Spatial Data Toolkit V2 用于重新定义现有空间数据工具的产品边界和信息架构。V2 的首个可交付版本聚焦设备点位，不建设通用 GIS 平台。

本文中的“V2”表示产品重构方向；“V1/MVP”表示该方向下的第一期交付范围。

### 0.2 现有项目审计

当前工作区可见内容以 `reference/gisviewer-react` 参考工程为主，顶层未发现可直接运行的目标产品源码、根级 `package.json` 或 `src` 目录。参考工程具备：

- React 18、TypeScript、Vite、React Router 基础；
- ArcGIS 2D/3D、Mapbox、SuperMap 等地图容器和图层能力；
- 天地图底图配置示例；
- Marker、海量点、聚合、轨迹、测量、搜索等较重的 GIS 功能；
- ArcGIS 空间参考与 CoordinateConversion 控件相关处理；
- 少量 localStorage 工具函数。

参考工程未发现以下目标产品能力：

- 点位统一数据模型与点位管理工作台；
- IndexedDB 点位库与导入记录；
- Excel/CSV/JSON 文件解析和字段映射流程；
- JSON 粘贴导入；
- WGS84、GCJ02、BD09、上海2000的统一转换服务及结果缓存；
- 高德、百度、天地图三个独立验证页面；
- API Key 配置和无 Key 时的阻断加载；
- 产品化首页。

因此，现有工程更适合作为地图实现参考，不应直接等同于 V2 产品基线。V2 应采用轻量、面向点位工作流的架构，按需复用经验证的地图展示思路，避免移植无关的轨迹、三维、绘制、热力图等能力。

### 0.3 关键技术前提

“上海2000”在现有参考代码中仅出现为“城建坐标”相关字段与地图配置，未发现明确的坐标参考定义、投影参数、转换参数或权威测试样本。开发前必须由业务方确认其准确含义，例如：

- 是否指上海城市坐标系/上海地方平面坐标；
- 轴顺序、单位、有效范围；
- 与 WGS84 或 CGCS2000 之间的转换参数；
- 至少 3 组权威双向校验样本及允许误差。

在以上定义确认前，可以完成接口、数据结构和 UI，但不得声称上海2000转换已可用于生产验证。

## 1. 产品定位

### 1.1 一句话定位

一个运行在浏览器中的设备点位坐标转换与地图验证工具。

### 1.2 产品目标

帮助用户在本地完成以下闭环：

1. 通过手动输入、文件或 JSON 粘贴导入设备点位；
2. 在统一列表中搜索、选择、查看和管理点位；
3. 按需生成目标坐标系坐标并缓存结果；
4. 在高德、百度、天地图中分别查看 Marker，验证展示位置；
5. 数据和密钥均保留在用户浏览器内，不依赖用户系统和后端。

### 1.3 产品原则

- **点位优先**：核心对象只有设备点位，不建设通用空间数据编辑器。
- **原始数据可追溯**：始终保留用户导入时的原始坐标和值所属坐标系。
- **按需转换**：目标坐标只在用户转换或地图展示需要时生成，生成后缓存。
- **平台隔离**：高德、百度、天地图使用独立页面和适配器，避免 SDK 相互污染。
- **本地优先**：点位与导入记录进入 IndexedDB，密钥和偏好进入 localStorage。
- **用户明确选择**：不自动猜测坐标系，不自动判断异常或所属区域。

### 1.4 成功标准

V1/MVP 达到以下结果即视为产品闭环成立：

- 用户能用三种入口新增点位，并在刷新浏览器后继续访问；
- 用户能对单个或多个点位生成指定坐标系坐标；
- 用户能选择点位并在三个地图页面分别显示；
- 地图页面仅在配置对应 Key/Token 后加载 SDK；
- 任一功能都不会上传点位、Key 或 Token 到本项目后端。

## 2. 用户角色

### 2.1 设备数据整理人员

持有 Excel、CSV、JSON 等设备清单，需要把名称和坐标整理为统一点位库。

核心诉求：

- 字段名不统一时可以手动映射；
- 明确指定整批文件的坐标系；
- 快速发现哪些目标坐标已生成；
- 不保留与定位无关的业务字段。

### 2.2 GIS/实施人员

需要将同一批设备点位转换到不同地图平台使用的坐标系，并验证落点。

核心诉求：

- 保留原始坐标；
- 支持 WGS84、GCJ02、BD09、上海2000；
- 支持批量转换；
- 在高德、百度、天地图独立验证。

### 2.3 测试与交付人员

需要复核设备位置是否能在客户使用的地图平台正常显示。

核心诉求：

- 搜索和选择目标设备；
- 快速切换到指定地图入口；
- 看到 Marker 并定位到选中点位范围；
- 本地配置平台密钥。

## 3. 使用场景

### 3.1 手工录入单个点位

用户进入 Point Manager，点击“新增点位”，填写名称、经度、纬度和坐标系。坐标系默认 WGS84。提交成功后表单清空，点位进入列表并立即持久化。

### 3.2 导入表格设备清单

用户上传 Excel 或 CSV，系统读取表头和预览行。用户分别选择点位名称、经度、纬度对应列，并为整份文件选择一个坐标系。确认后只提取这些字段，生成点位和一条导入记录。

### 3.3 导入 JSON 文件或粘贴 JSON

用户上传 JSON 文件或粘贴 JSON 数组。系统解析顶层对象数组、展示可选字段和预览。用户完成字段映射并选择一个坐标系后导入。

### 3.4 批量生成地图所需坐标

用户在列表勾选若干点位，点击“坐标转换”，选择目标坐标系。系统对每个点位从原始坐标或可靠的中间坐标进行转换，将结果写入该点位的坐标缓存。

### 3.5 地图验证

用户从列表的“地图查看”或地图页面的点位选择器选择点位。页面根据平台请求对应坐标：

- 高德地图：GCJ02；
- 百度地图：BD09；
- 天地图：WGS84。

若目标坐标尚未缓存，系统按需生成并保存。确认后地图显示 Marker，并自动调整视野覆盖所选点位。

## 4. 功能范围

### 4.1 V1/MVP 范围

#### 4.1.1 点位管理

- 手动新增点位；
- 搜索点位名称；
- 单选、全选当前结果；
- 单个删除和批量删除，删除前二次确认；
- 查看点位详情和已有坐标；
- 单个/批量坐标转换；
- 单个/批量地图查看；
- 浏览器本地持久化。

手动新增字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 点位名称 | 是 | 去除首尾空白后不能为空 |
| 经度/X | 是 | 必须可解析为有限数值 |
| 纬度/Y | 是 | 必须可解析为有限数值 |
| 坐标系 | 是 | 默认 WGS84 |

提交成功后关闭或重置表单，列表展示新增记录。V1 不做坐标系自动识别、区域判断和点位异常判断。

#### 4.1.2 文件导入

支持 `.xlsx`、`.xls`、`.csv`、`.json`。

统一流程：

1. 选择文件；
2. 浏览器端解析；
3. 展示文件基本信息、字段和样例预览；
4. 映射点位名称、经度、纬度字段；
5. 为整个文件选择一个坐标系；
6. 展示可导入数量和不可解析数量；
7. 用户确认后写入点位库和导入记录。

约束：

- 三个映射字段不得选择同一列；
- 一次导入只能选择一个坐标系；
- 只保存映射后的字段，不保存原始业务对象；
- 空行或映射值缺失/非数值的行不导入，只做解析结果统计，不进行“异常点”业务判断；
- 多工作表 Excel 在 V1 只导入用户选择的一个工作表，默认第一个可见工作表；
- JSON V1 仅支持顶层对象数组。

#### 4.1.3 JSON 粘贴导入

- 提供多行文本输入；
- 解析后进入与 JSON 文件相同的字段映射流程；
- 支持示例数据提示；
- 解析失败时显示可理解的错误，不写入数据库；
- 成功导入后清空粘贴内容。

#### 4.1.4 坐标转换

支持坐标系：

- WGS84
- GCJ02
- BD09
- 上海2000

入口位于 Point Manager，不提供独立核心页面。

能力：

- 单点转换；
- 批量转换；
- 地图页面按需转换；
- 已有相同目标坐标时直接使用缓存；
- 保留原始坐标，不允许转换动作覆盖原始值；
- 单次操作输出成功/失败数量。

#### 4.1.5 地图验证

保留三个独立路由：

- `/map/amap`
- `/map/baidu`
- `/map/tianditu`

每页由左侧 Sidebar 和右侧地图组成。Sidebar 至少包含：

- “选择点位”入口；
- 当前已选数量；
- 已选点位简表或空状态；
- 清空选择；
- 地图设置常驻按钮。

点位选择弹窗支持：

- 按名称搜索；
- 单选/多选；
- 全选当前搜索结果；
- 确认和取消；
- 保留打开弹窗前的选择，取消时不提交修改。

地图设置支持：

- 高德 Key；
- 百度 AK；
- 天地图 Token；
- 保存到 localStorage；
- 密钥输入默认遮罩，允许临时显示。

平台加载规则：

- 未配置当前平台密钥时，不注入或加载其地图 SDK，显示配置提示；
- 配置后才加载对应 SDK；
- SDK 加载失败时显示重试和设置入口；
- 地图只消费对应平台需要的坐标系；
- Marker 点击至少显示点位名称及当前展示坐标；
- 多点时自动适配视野，单点时使用合理默认缩放级别。

#### 4.1.6 首页

首页路由 `/`，用于产品介绍，不使用后台工作台布局。

内容：

- Hero：空间数据转换和地图验证；
- 功能介绍：点位管理、坐标转换、地图验证；
- 使用流程：导入数据 → 转换坐标 → 地图查看；
- 工具入口：Point Manager、高德地图、百度地图、天地图；
- 地图平台资源：各平台官网与 API 文档链接；
- 本地处理说明：数据保存在当前浏览器。

### 4.2 明确不在 V1/MVP 范围

- 自动识别坐标系；
- 点位异常判断、纠偏或质量评分；
- 行政区域/业务区域校验；
- GeoJSON；
- 用户注册、登录、权限和云同步；
- 后端接口和数据库；
- 通用图层管理、绘制、轨迹、热力图、三维地图；
- 地址解析、逆地理编码、路线规划；
- 点位导出（可作为后续版本）；
- 跨浏览器或跨设备迁移。

## 5. 信息架构与页面设计

### 5.1 路由

| 路由 | 页面 | 定位 |
| --- | --- | --- |
| `/` | 首页 | 产品介绍和入口 |
| `/points` | Point Manager | 数据工作台 |
| `/map/amap` | 高德地图验证 | GCJ02 Marker 验证 |
| `/map/baidu` | 百度地图验证 | BD09 Marker 验证 |
| `/map/tianditu` | 天地图验证 | WGS84 Marker 验证 |

新增、导入、详情、转换、点位选择和地图设置优先使用弹窗/抽屉，不增加不必要的一级路由。

### 5.2 全局导航

- Logo/产品名；
- 首页；
- Point Manager；
- 地图验证菜单（高德、百度、天地图）；
- 主题或基础设置入口（若 V1 实现主题配置）。

首页采用内容型导航；工作台和地图页采用工具型导航，但保持入口名称一致。

### 5.3 Point Manager

#### Header

- 标题：`Point Manager`
- 辅助说明：本地管理设备点位并生成地图坐标；
- 主操作：新增点位、导入文件；
- 导入入口中同时提供文件导入和 JSON 粘贴导入。

#### Toolbar

- 点位名称搜索；
- 已选数量；
- 坐标转换；
- 地图查看；
- 删除。

未选择点位时，批量操作禁用或引导用户先选择。

#### Table

默认列：

| 列 | 展示规则 |
| --- | --- |
| 选择框 | 支持单选和全选当前结果 |
| 点位名称 | 主识别字段 |
| 来源 | 手动、Excel、CSV、JSON 文件、JSON 粘贴 |
| 坐标状态 | 用标签展示已有坐标系数量/名称，不展开数值 |
| 操作 | 详情、转换、地图查看、删除 |

默认不把四套坐标全部展开为列。空列表展示新增和导入引导；无搜索结果展示清空搜索入口。

#### 点位详情

展示：

- 名称；
- 来源类型和可选的导入记录关联；
- 原始坐标及其坐标系；
- 所有已生成坐标；
- 每个坐标的生成时间；
- 继续转换入口。

### 5.4 导入弹窗/抽屉

建议采用分步结构：

1. 数据来源；
2. 数据预览与字段映射；
3. 坐标系与校验结果；
4. 导入结果。

导入确认前不写入 IndexedDB。大文件解析期间提供加载状态，并防止重复提交。

### 5.5 地图页面

左侧 Sidebar 固定宽度，右侧地图占剩余可视区域。小屏幕下 Sidebar 可收起为抽屉，但地图设置始终可访问。

状态设计：

- 未配置 Key：配置引导，不加载 SDK；
- SDK 加载中：加载状态；
- SDK 加载失败：错误说明、重试、打开设置；
- 未选择点位：显示选择引导，地图可以正常加载；
- 点位已选择：Marker 和列表联动；
- 个别转换失败：其余点位继续展示，并在 Sidebar 告知失败数量。

### 5.6 首页

首页强调清晰和快速进入，不展示点位表格或后台统计卡。平台资源链接应新窗口打开，并注明为第三方网站。

## 6. 数据模型

### 6.1 基础类型

```ts
type CoordinateSystem = 'WGS84' | 'GCJ02' | 'BD09' | 'SHANGHAI2000';

type PointSourceType =
  | 'manual'
  | 'excel'
  | 'csv'
  | 'json-file'
  | 'json-paste';

interface CoordinateValue {
  system: CoordinateSystem;
  x: number;
  y: number;
  generatedAt?: string;
}

interface PointCoordinates {
  original: CoordinateValue;
  converted: Partial<Record<CoordinateSystem, CoordinateValue>>;
}

interface PointSource {
  type: PointSourceType;
  importId?: string;
}

interface Point {
  id: string;
  name: string;
  source: PointSource;
  coordinates: PointCoordinates;
}
```

说明：

- `x/y` 作为通用存储字段；经纬度坐标在 UI 中显示为经度/纬度；
- 原始坐标只存一份，且不可被转换覆盖；
- `converted` 不重复保存与原始坐标系相同的值；
- 业务字段不进入 Point；
- 若需数据库索引时间，可作为存储层元数据处理，不扩张核心业务模型。

### 6.2 导入记录

```ts
interface ImportRecord {
  id: string;
  sourceType: Exclude<PointSourceType, 'manual'>;
  fileName?: string;
  sheetName?: string;
  coordinateSystem: CoordinateSystem;
  mapping: {
    name: string;
    x: string;
    y: string;
  };
  totalRows: number;
  importedRows: number;
  skippedRows: number;
  createdAt: string;
}
```

导入记录保存批次摘要和映射，不保存原始文件或完整原始行。

### 6.3 IndexedDB

建议数据库名：`spatial-data-toolkit`。

对象仓库：

| Store | Key | 建议索引 | 用途 |
| --- | --- | --- | --- |
| `points` | `id` | `name`、`source.type`、`source.importId` | 点位数据 |
| `imports` | `id` | `createdAt`、`sourceType` | 导入批次摘要 |

数据访问必须经 repository/service 层完成，页面组件不直接调用 IndexedDB API。数据库需定义 schema 版本和升级函数。

### 6.4 localStorage

建议使用带版本前缀的键：

| Key | 内容 |
| --- | --- |
| `sdt:v2:map-credentials` | 高德 Key、百度 AK、天地图 Token |
| `sdt:v2:theme` | 主题设置 |
| `sdt:v2:settings` | 基础设置 |

注意：

- localStorage 不是安全密钥库，设置页需提示密钥仅保存在当前浏览器；
- 不在日志、错误上报或 URL 中输出密钥；
- 地图 SDK 本身会向第三方平台发起请求，页面应明确这一事实。

### 6.5 坐标转换与缓存规则

转换服务统一接口：

```ts
interface CoordinateTransformer {
  transform(
    coordinate: CoordinateValue,
    target: CoordinateSystem
  ): Promise<CoordinateValue>;
}
```

规则：

1. 目标等于原始坐标系时返回原始值，不写重复缓存；
2. `converted[target]` 已存在时直接返回缓存；
3. 不存在时调用转换策略并保存；
4. 批量转换逐点记录结果，单点失败不回滚全部成功点；
5. 转换算法升级时应预留缓存版本或可失效策略，避免旧结果永久混用；
6. 上海2000转换只有在定义和权威样本确认后才能标记为可用。

平台坐标契约：

| 地图平台 | 展示坐标系 |
| --- | --- |
| 高德 | GCJ02 |
| 百度 | BD09 |
| 天地图 | WGS84 |

## 7. 非功能要求

### 7.1 隐私与安全

- 所有文件在浏览器端解析；
- 项目不建设点位上传接口；
- API Key/AK/Token 只写入 localStorage；
- 不将密钥写入源码、构建变量示例值或日志；
- 删除点位应二次确认。

### 7.2 性能

- 点位表格应支持分页或虚拟化，避免一次渲染全部记录；
- 文件解析和批量转换不阻塞主要交互；达到明显卡顿规模时使用 Web Worker；
- Marker 数量较大时使用平台聚合/海量点能力，具体切换阈值通过性能测试确定；
- V1 验收基准建议至少覆盖 10,000 个导入点位和 1,000 个同时展示 Marker，最终指标以目标设备测试结果为准。

### 7.3 兼容性

- 支持当前主流桌面版 Chrome、Edge；
- 需要 IndexedDB 和 localStorage；
- 移动端提供基本可访问布局，但不作为 V1 主工作环境。

### 7.4 可用性与可访问性

- 所有表单有明确标签和错误提示；
- 键盘可完成弹窗主要操作；
- 颜色不是坐标状态的唯一表达方式；
- 空状态、加载状态、错误状态和成功反馈完整；
- 删除、覆盖类操作有清晰确认。

## 8. 验收主流程

1. 首次打开应用，首页可进入 Point Manager；
2. 手动添加一个 WGS84 点位，刷新后仍存在；
3. 导入一份字段名非固定的 CSV，通过字段映射生成点位；
4. 粘贴 JSON 数组并完成映射导入；
5. 在列表勾选多个点位，批量生成 GCJ02 和 BD09；
6. 详情中能看到原始坐标与已生成坐标；
7. 未配置高德 Key 时进入高德页，SDK 不加载且出现配置提示；
8. 保存 Key 后选择点位，地图显示 Marker；
9. 百度和天地图分别使用 BD09、WGS84 展示；
10. 删除点位后刷新，记录不再出现。

## 10. 风险与待确认项

| 项目 | 影响 | 处理建议 |
| --- | --- | --- |
| 当前工作区缺少目标产品源码 | TASKS 中的文件路径只能按建议架构定义 | 开发开始前确认实际源码仓库/目录 |
| 上海2000定义不明确 | 无法保证转换正确性 | 提供正式参数、轴顺序、单位、样本和误差标准 |
| 地图平台 SDK 政策与 Key 限制 | 本地开发域名、生产域名可能无法共用 Key | 分平台验证控制台配置、域名白名单和配额 |
| 大文件/大量 Marker 性能 | 浏览器可能卡顿 | 建立性能基线，按需引入 Worker、虚拟表格、聚合 |
| localStorage 中的 Key 可被同源脚本读取 | 无法达到服务端密钥保密级别 | 明示风险、避免日志泄露、限制第三方脚本 |
| 坐标转换算法差异 | 不同库可能产生偏差 | 固定算法版本并用权威样本建立测试夹具 |
