## 1. 产品定位

### 1.1 一句话定位

> 一个运行在浏览器中的设备点位坐标转换与地图展示工作台。

### 1.2 核心价值

Coordinate Toolkit 帮助用户把来源不同、字段不同、坐标系不同的设备点位整理为统一点位库，按需生成目标坐标，并在高德、百度、天地图中展示和核对落点。

核心价值：

- 点位数据在浏览器本地处理；
- 原始坐标始终可追溯；
- 同一批点位可转换到多个坐标系；
- 三个地图平台分别验证，避免平台坐标差异造成偏移；
- 不要求用户部署后端或创建账户。

### 1.3 产品边界

Coordinate Toolkit 是专业地图工具，但不是：

- 通用 GIS 平台；
- 企业设备管理后台；
- 在线协作数据库；
- 地图 SDK 功能演示；
- 自动数据质量判断系统。

### 1.4 产品原则

- **点位为核心对象**：V1 只处理点位；
- **用户明确选择**：字段和坐标系由用户确认；
- **原始数据不可覆盖**：转换结果独立缓存；
- **按需转换**：需要时生成目标坐标；
- **地图平台隔离**：共用地图工作台外壳，各平台使用独立 Adapter、工具栏、状态与生命周期；
- **本地优先**：点位进入 IndexedDB，设置进入 localStorage；
- **能力诚实**：不使用空实现、推测结果或伪成功。

## 2. 重构原则

本项目采用：

> 功能复用，架构重构，UI 重做。

### 2.1 功能复用

- `map-tools` 是已有业务能力的主要参考来源；
- 对已经正确、经过验证且满足新需求的业务逻辑，优先迁移和模块化封装；
- 坐标转换、Excel/CSV 解析、字段匹配、点位转换流程、地图坐标映射等逻辑必须先审计和测试，再决定迁移方式；
- 不重新发明坐标转换算法；
- 不因目录、命名或框架变化而删除成熟能力。

“复用”不等于复制整个文件或项目结构。迁移前必须确认输入、输出、边界条件、测试样本和新数据模型是否一致。

### 2.2 架构重构

- 重新划分 Point、Coordinate、Import、Map、Storage 等模块边界；
- 将坐标转换从页面 Hook 中分离为可测试的核心服务；
- 将文件解析、字段映射和导入提交分离；
- 将高德、百度、天地图封装为明确的 MapAdapter；
- 将页面与 IndexedDB、地图 SDK 隔离；
- 以最小必要抽象解决真实问题，不为架构形式牺牲简单性。

### 2.3 UI 重做

- 统一使用 PeachTools Design System；
- 保留旧项目已验证的业务流程，但重新设计信息架构、页面布局、状态反馈和可访问性；
- 首页、点位管理、地图展示工作台分别采用适合其任务的布局；
- 不沿用旧项目不一致的视觉样式和页面耦合。

### 2.4 参考项目职责

| 项目 | 主要用途 | 使用原则 |
| --- | --- | --- |
| `map-tools` | 业务能力参考 | 优先验证成熟逻辑，按新模块边界迁移 |
| `gisviewer-react` | 地图架构参考 | 提取容器、配置、能力分层和生命周期思想 |
| Coordinate Toolkit V2 | 产品化实现 | 不复制旧结构，建立统一数据、UI、存储和 Adapter |

### 3.3 迁移判断标准

每项已有能力进入 V2 前必须归类：

- **直接迁移后封装**：逻辑正确、边界清晰、测试可补齐；
- **保留思路并重构**：业务行为正确，但结构、类型或生命周期不满足 V2；
- **重新实现**：旧实现存在明确正确性、安全或维护问题；
- **不迁移**：超出 V1 或偏离产品定位。

## 4. 目标用户

### 4.1 设备数据整理人员

需要从 Excel、CSV 或 JSON 中提取点位名称和坐标，形成统一点位清单。

### 4.2 GIS/项目实施人员

需要把设备点位转换到不同地图平台使用的坐标系，并检查落点。

### 4.3 测试与交付人员

需要在指定地图平台中复核点位是否正确显示。

## 5. 核心流程

```mermaid
flowchart LR
    A["导入点位"] --> B["点位管理"]
    B --> C["坐标转换"]
    C --> D["地图展示"]
```

### 5.1 导入点位

用户通过手动输入、Excel、CSV、JSON 文件或 JSON 粘贴提供点位。文件/JSON 导入时明确映射名称、经度/X、纬度/Y字段，并为整批数据选择一个坐标系。

### 5.2 点位管理

导入结果进入点位管理和 IndexedDB。用户可以搜索、选择、查看详情和删除点位。

### 5.3 坐标转换

用户对单个或多个点位选择目标坐标系。系统保留原始坐标，将成功结果写入该点位的转换缓存。

### 5.4 地图展示

用户选择点位和地图平台。系统取得平台要求的坐标；若尚未生成则提示用户先完成转换。地图展示 Marker，用户通过实际底图核对落点。

## 7. 使用场景

### 7.1 手动添加单点

1. 用户进入点位管理；
2. 点击“新增点位”；
3. 填写名称、经度/X、纬度/Y；
4. 选择坐标系，默认 WGS84；
5. 保存；
6. 输入清空，点位进入列表并持久化。

### 7.2 Excel/CSV 导入

1. 用户选择文件；
2. 系统在浏览器端解析；
3. 显示工作表（Excel）、字段和预览；
4. 用户映射名称、经度/X、纬度/Y；
5. 用户为整份文件选择一个坐标系；
6. 系统统计可导入和跳过行；
7. 用户确认；
8. 点位和导入记录写入 IndexedDB。

### 7.3 JSON 文件/粘贴导入

V1 支持顶层对象数组，例如：

```json
[
  {
    "name": "设备1",
    "lng": 121.4,
    "lat": 31.2
  }
]
```

解析成功后进入与表格文件相同的字段映射和坐标系选择流程。

### 7.4 批量转换

1. 用户在点位列表选择点位；
2. 点击“坐标转换”；
3. 选择目标坐标系；
4. 系统逐点处理；
5. 成功结果缓存；
6. UI 显示成功和失败数量；
7. 列表坐标状态更新。

### 7.5 地图查看

1. 用户从点位管理点击“地图查看”，或直接进入地图展示工作台；
2. 选择一个或多个点位；
3. 系统准备当前平台坐标；
4. 地图展示 Marker；
5. 点击 Marker 查看名称和展示坐标；
6. 多点时自动调整视野。

### 9.3 导入

建议四步：

1. 选择数据；
2. 预览和字段映射；
3. 选择坐标系并检查统计；
4. 导入结果。

规则：

- 名称、X、Y字段必选；
- 三个字段不能重复；
- 一个导入批次只能选一个坐标系；
- 确认前不写数据库；
- 只保存 Point 所需字段；
- 非数值/缺失行跳过并统计，不称为异常点；
- Excel V1 选择一个工作表，默认第一个可见工作表；
- JSON V1 只支持顶层对象数组。

### 9.4 地图展示工作台

布局：

```text
┌──────────── Sidebar ────────────┬──────── Map ────────┐
│ 选择点位                         │                     │
│ 已选点位                         │      Markers        │
│ 清空                             │                     │
│ 地图设置                         │                     │
└─────────────────────────────────┴─────────────────────┘
```

Sidebar：

- 地图平台切换；
- 选择点位；
- 名称搜索；
- 单选/多选/全选当前结果；
- 已选点位列表；
- 清空；
- 地图设置。

平台隔离规则：

- 公共 `MapAdapter` 只包含 `mount`、`setPoints`、`fitView`、`clear`、`destroy`；
- 平台专属底图、路况、导航、注记和控件能力不进入公共接口；
- 切换平台时销毁旧实例，清除 Marker、InfoWindow、覆盖物和事件；
- 同一时刻只保留当前平台地图实例，不缓存三套 SDK 对象；
- Point 数据和平台轻量 UI 设置可以跨平台切换保留；
- 三个平台 SDK script 各自只加载一次。

地图状态：

- 未配置凭据；
- SDK 加载中；
- SDK 加载失败；
- 未选择点位；
- 正常展示；
- 部分点位转换失败。

## 10. API Key 设置

支持：

- 高德 Key；
- 百度 AK；
- 天地图 Token。

规则：

- 保存到 localStorage；
- 输入默认遮罩；
- 不写入 URL、日志或源码；
- 没有当前平台凭据时不注入 SDK script；
- 清空凭据后当前平台停止加载；
- 提示 localStorage 不是安全密钥库；
- 说明地图 SDK 会向第三方平台发起请求。

## 11. 数据模型

### 11.1 坐标体系状态

#### 正式支持

- WGS84
- GCJ02
- BD09
- 上海2000

四种坐标系作为 V1 用户入口、Point 原始坐标类型和转换目标。

#### 扩展验证

- CGCS2000

CGCS2000 与 WGS84 属于不同坐标基准体系，不能在产品定义上简单视为同一坐标系。旧项目把 CGCS2000 作为天地图目标坐标并在部分转换中近似按 WGS84 处理；V2 需要保留该已有能力线索，但在开发阶段验证实际业务数据、地图平台契约、转换必要性和误差。

CGCS2000 默认不作为 V1 用户入口。验证结论可为：

1. 仅作为地图 Adapter 内部坐标契约；
2. 作为高级扩展坐标类型；
3. 当前业务不单独需要，使用明确记录的兼容策略。

任何结论都必须有测试样本和书面技术决定。

### 11.2 CoordinateSystem

```ts
type CoordinateSystem =
  | 'WGS84'
  | 'GCJ02'
  | 'BD09'
  | 'SHANGHAI2000';
```

### 11.3 Coordinate

```ts
interface Coordinate {
  system: CoordinateSystem;
  x: number;
  y: number;
  generatedAt?: string;
  algorithmVersion?: string;
}
```

说明：

- 经纬度坐标 UI 显示为经度/纬度；
- 上海2000显示为 X/Y；
- 数据库存储完整数值，展示格式不改变存储值；
- 转换坐标可记录生成时间和算法版本。

### 11.4 Source

```ts
type PointSourceType =
  | 'manual'
  | 'excel'
  | 'csv'
  | 'json-file'
  | 'json-paste';

interface Source {
  type: PointSourceType;
  importId?: string;
}
```

### 11.5 Point

```ts
interface Point {
  id: string;
  name: string;
  source: Source;
  coordinates: {
    original: Coordinate;
    converted: Partial<Record<CoordinateSystem, Coordinate>>;
  };
}
```

约束：

- Point 只保留 `id`、`name`、`source`、`coordinates`；
- 不保存原始业务对象；
- original 不可被转换覆盖；
- 与 original 同坐标系的值不重复写 converted；
- converted 按需生成。

### 11.6 ImportRecord

```ts
interface ImportRecord {
  id: string;
  sourceType: Exclude<PointSourceType, 'manual'>;
  fileName?: string;
  sheetName?: string;
  coordinateSystem: CoordinateSystem;
  mapping: {
    name: string;
    x: string;
    y: string;
  };
  totalRows: number;
  importedRows: number;
  skippedRows: number;
  createdAt: string;
}
```

导入记录不保存原始文件或完整原始行。

## 12. 本地存储

### 12.1 IndexedDB

数据库建议：`coordinate-toolkit`。

| Store | Key | 用途 |
| --- | --- | --- |
| `points` | `id` | 点位 |
| `imports` | `id` | 导入批次摘要 |

要求：

- 有升级策略；
- 页面不直接调用 IndexedDB；

- 失败不生成成功导入记录。

## 13. 坐标转换规则

### 13.1 基本规则

1. 用户明确选择源坐标系；
2. 目标等于 original.system 时返回原始值；
3. converted 中已有目标时使用缓存；
4. 缺失时调用转换服务；
5. 成功后写入缓存；
6. 单点失败不回滚其他点成功结果；
7. 失败不得返回 `(0, 0)` 等伪坐标。

### 13.2 地图坐标契约

| 平台 | 目标坐标 |
| --- | --- |
| 高德 | GCJ02 |
| 百度 | BD09 |
| 天地图 | 开发前根据官方契约和测试样本最终确认；产品展示统一使用选定契约 |

旧资料同时出现“天地图使用 CGCS2000”和“V1 正式支持 WGS84/GCJ02/BD09/上海2000”两种口径。V2 将 CGCS2000 列为扩展验证，不默认加入用户入口；天地图 Adapter 的输入坐标契约需结合旧项目逻辑、官方资料和实际样本确认。若确认以 WGS84 兼容展示，必须记录适用范围和误差；若业务需要独立管理 CGCS2000，则通过扩展能力评审启用。

### 13.3 上海2000

`map-tools` 已提供上海2000与 CGCS2000 之间的 proj4 转换基础和参数配置，因此 V2 不把上海2000视为“无法实现”的能力。开发阶段应在现有基础上完成验证，再正式启用。

验证内容：

- 正式坐标参考定义；
- 轴顺序；
- 单位；
- 投影/转换参数来源；
- 适用区域；
- EPSG 信息或地方坐标参考的等价权威说明；
- 至少 3 组权威双向测试样本；
- 可接受误差。

验证通过后，上海2000作为正式支持坐标系启用。验证未完成时应明确标记“待验证”，不得用未经确认的参数产生静默结果，但也不应删除已有转换基础。

## 14. 非功能要求

### 14.1 隐私

- 文件只在浏览器处理；
- 不建设点位上传接口；
- 不记录点位或 Key 到远程日志；
- 第三方地图请求边界在 UI 中说明。

### 14.2 性能

- 点位列表支持分页或虚拟化；
- 导入预览不渲染全部行；
- 大文件评估 Web Worker；
- 地图根据点数选择普通 Marker、聚合或海量点；
- V1 建议测试 10,000 点导入和 1,000 点地图展示。

### 14.3 兼容性

- 主要支持当前桌面 Chrome、Edge；
- 需要 IndexedDB 和 localStorage；
- 所有外部资源使用 HTTPS；
- 移动端保证关键流程可访问，但不是 V1 主环境。

### 14.4 可访问性

- 输入有标签；
- 键盘可完成主要操作；
- 状态不只依赖颜色；
- Dialog 焦点管理正确；
- 地图不是点位信息的唯一表达。

## 15. V1 验收主流程

1. 首页可进入点位管理；
2. 手动添加 WGS84 点位，刷新后存在；
3. Excel 导入可选择工作表和字段；
4. CSV 导入可正确处理中文和引号；
5. JSON 文件和粘贴都可进入字段映射；
6. 非法行被跳过并统计，不生成 `(0, 0)`；
7. 列表可搜索、选择、查看详情和删除；
8. 单个/批量转换可生成并缓存目标坐标；
9. 未配置地图凭据时不加载 SDK；
10. 配置后高德、百度、天地图分别显示所选点位；
11. Marker 点击显示名称和当前展示坐标；
12. 删除点位后刷新不再出现；
13. 项目不存在用户系统、后端、GeoJSON和自动坐标识别入口。

## 16. 成功标准

- 新用户无需阅读 GIS 手册即可完成核心流程；
- 原始坐标不会因转换丢失；
- 同一目标坐标不会无故重复计算；
- 地图工作台对三个平台的无凭据、加载失败和转换失败有明确反馈；
- 数据刷新后可恢复；
- V1 范围没有被非核心地图工具稀释。
